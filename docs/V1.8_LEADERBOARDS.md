# V1.8 — Real Leaderboards Foundation

## Goal
Prepare the casual-game collection for production leaderboard integration without coupling gameplay code to a specific backend provider.

## Scope
- Provider-neutral leaderboard submission/query contract.
- Leaderboard entry model with player identity, game ID, score, rank and server timestamp metadata.
- Explicit score submission result states: accepted, rejected, offline, retryable and unavailable.
- Idempotent submission IDs to prevent duplicate score writes during retries.
- Local best-score preservation when the service is unavailable.
- Clear separation between client display data and server-authoritative ranking.
- Security requirements for authenticated submission, server-side score validation, anti-cheat checks and rate limiting.
- Offline queue/retry boundary; no claim of live backend connectivity.

## Integration Rules
1. Gameplay systems must submit scores through the leaderboard service boundary.
2. The client must never assign its own authoritative rank.
3. Server responses are the source of truth for rank and accepted score state.
4. Failed submissions remain retryable without duplicating transactions.
5. No service-role credentials or privileged backend keys may ship in the Unity client.

## Acceptance Criteria
- Contract and models compile conceptually against the existing architecture.
- Submission IDs are deterministic per score event and safe to retry.
- Local best scores remain available offline.
- UI can distinguish local/offline data from server-confirmed leaderboard data.
- Production backend, authentication, RLS, validation and device QA remain explicit release gates.
